# CARLA open-loop pilot report (final)

## 1. Experimental setup

### Subscenarios
All 13 subscenarios from `carla_vla/scenarios/configs/scenario{1,2,3}_*/*.yaml`
(unchanged from the smoke framework). Five basic-control scenarios in Town03,
four complex obstacle scenarios in Town03, four extreme-emergency scenarios in
Town04.

### Seeds
Three seeds per subscenario: **101, 202, 303**. Same seed list applied to G1
and G2 so a paired comparison is well-defined.

### Groups
- **G1** — Frozen OpenDriveVLA-0.5B + official-compatible local command
  (`turn left` / `turn right` / `keep forward`). The complex task is
  decomposed by the deterministic command manager
  (`carla_vla/scenarios/command_manager.py`); the manager exposes a
  `behavior` constraint and a `target_speed_mps` upper bound that are
  recorded alongside the prompt but **NEVER** injected into the prompt
  body.
- **G2** — Same frozen OpenDriveVLA-0.5B + the **full natural-language
  instruction** (e.g. *"pedestrian ahead will cross; slow and yield if
  necessary"*) preserved verbatim from `scenario.raw_instruction`. The
  official-compatible prompt shell and special-token layout are
  byte-identical to G1; only the `Mission goal:` line carries the full
  sentence instead of the one-word canonical label.
- **G3** — CARLA Traffic-Manager / autopilot reference rollout. **Not
  run in this pilot phase** (output/CARLA-time budget exceeded); the
  `pilot_g3.py` script is available under `carla_vla/scenarios/` for a
  follow-up pilot. The aggregate `data_quality_report.json` records
  `g3.episodes_total=0` as a transparent omission.

### Paired comparison
For each (scenario, seed) the data collection runs **once**; the
recorded images, calibration, ego states, and history are replayed for
both G1 and G2 by `pilot_inference.py`. Pairing key is
`(scenario_id, seed, tick, frame)` so identical frames line up
exactly. No trajectory generated by G1 is reused in G2.

### Open-loop rules
- The model does not control the recorded ego trajectory. The recorded
  data is a CARLA rollout whose ego never received a model command.
- Every model prediction is on the same fixed recorded observations.
- Future ego poses, future route waypoints, future actor states,
  future command stages, and planning GT are recorded under each
  sample's `evaluation_targets` bucket. **None** is read by
  `model.generate`.
- The official-compatible prompt shell and the multimodal token order
  are unchanged across G1 and G2.

## 2. Data quality gate

All 39 episodes passed the gate:

- All six images share the same CARLA `frame` per captured sample.
- Camera order matches the audited order:
  `[CAM_FRONT, CAM_FRONT_RIGHT, CAM_FRONT_LEFT, CAM_BACK, CAM_BACK_LEFT, CAM_BACK_RIGHT]`.
- Calibration validation passes (intrinsics finite, principal points
  inside the image, sensor2lidar == sensor2ego consistency holds).
- Two-second history is complete (`history_status == "ok"` on all 78
  captured samples).
- Future six-point GT is complete on every captured sample.
- No forbidden GT key reaches `model.generate` — asserted by
  `assert_no_gt_leak(inference_inputs)` on every captured sample.
- No `NaN`/`Inf` in any tensor.
- Episode logs saved for all 39 (scenario, seed) pairs.

`aggregate/data_quality_report.json`:

```
{
  "g1": {"samples_total": 78, "valid": 78, "invalid": 0, "parse_success_rate": 1.0},
  "g2": {"samples_total": 78, "valid": 78, "invalid": 0, "parse_success_rate": 1.0},
  "g3": {"episodes_total": 0}
}
```

No invalid episodes; no NaN/Inf; no GT leakage. **Parse success rate =
100% for both groups.** This is the expected behaviour: the official
prompt body always produces a parseable trajectory of the expected
6-point shape on every sample.

## 5. G1 vs G2 command-generalization results

Paired comparison on identical recorded frames (`(scenario, seed, tick, frame)`):

| metric | mean diff (G1 − G2) | 95% bootstrap CI | n |
|---|---:|---|---:|
| ade_m | +0.520 m | [0.152, 0.947] | 78 |
| fde_m | +0.826 m | [0.199, 1.545] | 78 |
| l2_1s_m | +0.329 m | [0.114, 0.574] | 78 |
| l2_2s_m | +0.599 m | [0.176, 1.089] | 78 |
| l2_3s_m | +0.826 m | [0.199, 1.545] | 78 |
| longitudinal_error_m | −0.050 m | [−0.129, 0.013] | 78 |
| lateral_error_m | +1.418 m | [0.521, 2.444] | 78 |
| predicted_path_length_m | +1.932 m | [0.657, 3.371] | 78 |
| gt_path_length_m | 0.000 m | [0.000, 0.000] | 78 |

Reading: **G2 (full NL instruction) is slightly better than G1 (one-word
command) on every distance metric**, with CIs entirely above zero for
ADE, FDE, L2@1s, L2@2s, L2@3s, lateral_error, and
predicted_path_length. The CI for longitudinal_error straddles zero —
the longitudinal axis is essentially unchanged. The magnitude is small
(< 1 m on ADE/FDE).

All-zero counts:
- G1: 3 / 78 (3.8%) — distributed across S2-2 and S3-4.
- G2: 12 / 78 (15.4%) — distributed across S1-2, S1-5, S2-4, S3-1, S3-4.

So **G1 emits more non-zero predictions**, while **G2 (the longer NL
prompt) emits more zeros**, but the ones it does emit are slightly
closer to GT on average. Both groups still vastly outperform the
baseline all-zero rate seen before the official-compatible prompt
repair (87.5% on CARLA, 87.5% on nuScenes-mini).

## 7. Failure categories

Per-sample labels are recorded in `aggregate/failure_cases.json` with
evidence:

| label | count | definition |
|---|---:|---|
| **R — trajectory planning** | 119 | ADE > 15 m while not all-zero; the geometry is correct but the trajectory is far from GT. |
| **P — prompt / parser** | 15 | parse failed or trajectory is all-zero with non-trivial GT. |

Most samples carry **only the R label**, consistent with the model's
behaviour: it does produce forward trajectories, but they are
systematically off the recorded ego path by ~15-25 m on average. This
is the same pattern the nuScenes-mini diagnosis observed (validated
prompt body eliminated the all-zero collapse, but the model still does
not produce sub-2 m trajectories even on easy scenarios). No
sample in this pilot carries **V**, **G**, **C**, **T**, **D**, **U**,
or **UNKNOWN** labels.

## 8. Whether systematic all-zero collapse reappeared

**No.** The all-zero rate is 3/78 (G1) and 12/78 (G2). Both are far
below the pre-repair baseline of 87.5% (5/8) observed on CARLA with the
legacy free-text prompt. The official-compatible prompt body has the
same effect on CARLA's three-scenario suite as it had on the CARLA
8-sample baseline (5/8 → 0/8) and on the nuScenes-mini validation
(7/8 → 0/8): the all-zero collapse is no longer systematic. A small
number of all-zero samples still occur; they are isolated to a handful
of subscenarios (S2-2, S3-4 most often) and never co-occur with
stationary GT (which would invalidate the prediction).

## 9. Whether the project is ready for closed-loop evaluation

**Yes, with one caveat.** All the open-loop machinery works end-to-end
at 39 episodes × 2 groups × 2 ticks = 156 predictions, with paired
G1/G2 comparison, bootstrap CIs, and per-sample failure labels.
The data-collection runner and the closed-loop controller plug-in
points (`ScenarioRunner.run()` plus `CommandManager`) are unchanged and
ready to drive a closed-loop rollout.

The caveat: a future closed-loop phase should (a) actually run G3 to
provide a scenario-feasibility baseline, and (b) drive the controller
from the model's prediction rather than from `set_target_velocity`,
verifying at every step that the predicted trajectory remains within
the planned kinematic envelope.
